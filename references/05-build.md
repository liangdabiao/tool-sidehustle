# 阶段 5：开发上线

## 5.1 产品/技术六条建议

1. **域名**：买「有建站记录、无不良记录」的老域名（新站沙盒期短）。
2. **架构**：优先 B/S（网页工具）而非 C/S（桌面软件）——便于维护更新、运营推广，变现选择多（广告+会员+付费功能）。
3. **系统**：能用现成 CMS 就不自己写（站群/内容/SEO 基建现成）。
4. **迭代**：优先满足最核心的基本功能，**立刻上线**，先确定商业价值再逐步优化。不要憋大招。
5. **服务器**：阿里云/腾讯云几十块/月的即可，后续再升配。
6. **源码**：不重复造轮子，先 GitHub 等找现成源码修改。

## 5.2 界面设计：极简还是复杂，取决于用户群体

不是绝对的「越简单越好」，核心问题：**用户是谁？用户用这个工具时的诉求是什么？**

- **通用工具，面向大众** → 极简。理想状态是一个文本框+一个按钮（如百度首页；它的高级搜索从不主动介绍）。用户「只想在线给图片加个水印」，你让他下载安装 PS 就错了。判断标准：用户是否会为了这个功能去学习你的工具、甚至下载安装？不会 → 控件能少则少，傻瓜化，让用户少做决策。
- **专业工具，面向专业人士** → 功能丰富反而是友好（如百度推广客户端凌乱但投放人员需要）。用户本来就要把事做完整，功能多=配置能力强，熟悉操作只要几小时（如设计海报的人可以接受 PS 的满屏窗口）。

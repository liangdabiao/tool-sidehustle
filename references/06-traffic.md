# 阶段 6：流量策略

原则：流量必须来自搜索（被动、可积累），不靠发给别人（主动、一次性）。一切的基础是**最大程度挖掘这款工具的长尾流量词**：
- 基于核心描述的延伸词：「图片压缩」→「在线图片压缩工具」
- 同义但不含核心描述的词：「几M的图怎么变成几K」（这类词靠阶段 1 的关联查询+发散拿到）

## 6.1 标题轮换法（快速找到能上首页的词）

不要理所当然把首页 title 设为「图片压缩工具」——有竞争就上不去。流程：

1. 收集该工具所有长尾词 → 批量查搜索量 → 按搜索量**降序**排列。
2. 从上往下选一个觉得「可以试试」的词，设为首页 title。
3. 提交收录：把链接放到百度搜索框查一下（新站几天收录）；有资源平台账号就走普通收录提交。
4. 到多台电脑/不同 IP 搜目标词，看站点是否进首页。
5. 没进首页 → 换下一个词改 title → 重新提交（原「投诉快照」流程已下线，改用百度搜索资源平台的普通收录/快速收录提交，或等重新抓取）。
6. 循环，直到找到能排到首页的词，title 定稿。
7. 装百度统计，验证该词是否每天带来流量、量是否可观。不可观也先接受——这是快速复位重试的验证法（类似游戏过不了关就复位重来）。

注意事项：
- 新站暂时不要选搜索量大的词（避免反复改）。
- 原文经验：专题页标题通过「修改→更新→查询」循环优化，效果明显且可预见。
- 若阶段 3 筛选到位（找到流量错位），这一步很好选词，因为竞争小。

**两个小思考（原文，值得执行时琢磨）**：
1. 「流量不可观暂时没办法」是因为已经开发了；如果还没开发呢？（→ 先用低成本页面测词，再决定开发）
2. 一个只有输入框+按钮的页面，搜索引擎无法自动判断功能是否真的有效。（→ 页面要有内容、有结果呈现，帮助引擎理解）

## 6.2 长尾单页（一个功能一个页面）

核心功能带来的流量少时，用收集到的长尾词**选出延伸功能**，每个功能做一个单页承载对应流量。有多少延伸功能，就有多少长尾流量。
标杆：PDF 站围绕「PDF转换」延伸出 转Word/转PPT/加水印/删页面/合并/分割/加密/统计字数… 每个功能独立 URL（见 cases.md）。

## 6.3 知乎引流（屡试不爽，可自动化布局）

1. 对该工具的全部长尾词再批量查一次 SERP。
2. **统计搜索结果第一页没有知乎链接的词**——这就是引流机会。
3. 一个词写一篇知乎文章（非常相似的两词合一篇），**标题完全命中搜索词**。
4. 文章发布后把链接提交搜索引擎（放百度搜索框 / 资源平台提交），一般几小时~隔天收录。
5. 长尾词 + 完全命中标题的知乎文章，很容易马上排到首页（必须是长尾词，大词不行）。
6. 文章内容：可以是链接、工具名、网盘链接 + 简单几句介绍，目标词出现一下即可。
7. 大量布局 → 明显的长尾流量。原文实测：挑「统计字数」类长尾词做标题，白号发文，收录后直接首页第 7 名，几个月平均每天带来 5-10 个下载。

贴吧/知道/经验等回复留工具名属锦上添花，需要长期积累。**引流只做可积累的**：发论坛=可反复曝光，发群=一次性曝光。

## 6.4 流量检验

百度统计看每个词/页面的实际来路流量 → 反哺阶段 1：哪些词有真实流量就延伸哪些功能页。

# 阶段 3：筛选策略

目标：对每个代表词做百度 SERP 批量查询，用数据规则淘汰竞争激烈的需求。产出：透视表 + 幸存词清单。

## 3.1 批量查询与原始数据

对每个代表词查询百度 SERP，分别记录：

- **竞价**：广告标题 + url（标题保留 `<font>` 飘红标签，用于判断飘红词）
- **自然排名**：每条标题 + url（百度快照链接要还原成原始链接；快照已下线，直接取结果 url）
- **收录量**：SERP 显示的「为您找到相关结果约 N 个」

原始数据表列（`03_filtered/raw.csv`）：

```
word, type(ad|rank), position, title, url, domain, nums(收录量), scraped_at
```

用脚本抓（低频+UA 伪装），被反爬时改走 bsk 浏览器逐词抓。百级样本用 bsk 目检即可。

## 3.2 透视表

按代表词聚合出：`word, ad_count, avg_weight, min_weight, nums`（词, 竞价数量, 自然排名平均权重, 最小权重, 收录量）。

## 3.3 五条筛选规则（按序执行）

1. **竞价基线校准先行**：每个垂直开跑前，先用 2-3 个对照词测出当期 SERP 的**广告基线**（2026-11 实测：商业类词基线即 4-5 条）。当基线 ≥5 时，广告数作为参考项，竞争判断以规则 2 的**自然结果域名质量**为主轴。
2. **竞价相关性校验**：广告标题必须飘红该词的**核心词**（阶段 2 的 cluster_key）才计入有效竞价。如搜「图片压缩工具」，广告飘红「压缩/图片」→ 真竞价；飘红的是「图片处理」→ 与该需求无关，不计入。
3. **收录量 ≥ 10,000,000 的词，去掉。**
4. **自然结果域名质量校验（主轴）**：用 curl `mu=` 属性提取自然结果真实域名，按质量分级——
   - 前列多为**品牌工具站/大厂** → 垄断，标注绕开（如 ai配音被讯飞/微软占据）
   - 前列多为**无名小站** → 竞争弱，机会词（如 ai漫剧全部为无名站）
   - 前列多为**教程/内容页**（CSDN/知乎/个人博客）→ 工具供给弱，内容号/合集页机会
   - 辅助验证权重：爱站 `https://www.aizhan.com/cha/<domain>/` 免登录；5118 API `apis.5118.com/weight`（需 key）
5. **搜索量 topN 的词去掉**（N 按数据量相对设定）。
   搜索量查询：5118 API `apis.5118.com/keywordparam`（约 ¥0.008/次）；有百度竞价账户可用关键词规划师免费批量查。10 万词约几百块成本。

**ps**：同类多个词抽代表时选最短的（原因见 02）。

## 3.4 小策略：发现「无人做 Web 版」的错位机会

用户极不愿意为小工具下载安装软件。做法：

1. 预先收集一批**软件下载站域名**（如各类下载站/大站域名）。
2. 对每个幸存词检查 SERP：若结果几乎全是下载站或大站域名 → 该需求很可能还没有 Web 版供给（技术门槛/场景门槛造成的错位）→ **机会词**。
3. 词里明确带「在线」词缀的，用户对 Web 版期待最强，优先级更高。

## 3.5 产出

`03_filtered/survivors.csv`：幸存词 + 各项竞争指标 + 是否「下载站错位」标记。交给阶段 4 人工验证。

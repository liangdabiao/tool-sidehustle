# 阶段 3：筛选策略

目标：对每个代表词做百度 SERP 批量查询，用数据规则淘汰竞争激烈的需求。产出：透视表 + 幸存词清单。

## 3.1 批量查询与原始数据

对每个代表词查询百度 SERP，分别记录：

- **竞价**：广告标题 + url（标题保留 `<font>` 飘红标签，用于判断飘红词）
- **自然排名**：每条标题 + url（百度快照链接要还原成原始链接；快照已下线，直接取结果 url）
- **收录量**：SERP 显示的「为您找到相关结果约 N 个」

原始数据表列（`03_filtered/raw.csv`）：

```
word, type(ad|rank), position, title, url, domain, nums(收录量), scraped_at
```

用脚本抓（低频+UA 伪装），被反爬时改走 bsk 浏览器逐词抓。百级样本用 bsk 目检即可。

## 3.2 透视表

按代表词聚合出：`word, ad_count, avg_weight, min_weight, nums`（词, 竞价数量, 自然排名平均权重, 最小权重, 收录量）。

## 3.3 四条筛选规则（按序执行）

1. **竞价数量 ≥ 5 的词，去掉。**
   但要先校准：竞价存在词语匹配问题。判断标准——广告标题里必须飘红该词的**核心词**（阶段 2 提取的 cluster_key）。如搜「图片压缩工具」，两条广告标题都飘红「压缩/图片」→ 真竞价；若广告是「图片处理工具_百度AI多种优化」不飘红「压缩」→ 与该需求无关，不计入。
2. **收录量 ≥ 10,000,000 的词，去掉。**
3. **自然排名前 10 站点的「最小权重」> 3 的词，去掉。**
   10 个结果里权重最小的那个 > 3，说明挤进首页有难度（经验阈值，可按数据调整）。权重用爱站（作者习惯）/5118 查询：爱站 `https://www.aizhan.com/cha/<domain>/` 免登录可见百度 PC/移动、360、必应、神马权重；5118 API `apis.5118.com/weight`（需 key）。
4. **搜索量 topN 的词去掉**（N 按数据量相对设定）。
   搜索量查询：5118 API `apis.5118.com/keywordparam`（约 ¥0.008/次）；有百度竞价账户可用关键词规划师免费批量查（输入词表 → 返回月均搜索量/竞争度/指导价）。10 万词约几百块成本。

**ps**：同类多个词抽代表时选最短的（原因见 02）。

## 3.4 小策略：发现「无人做 Web 版」的错位机会

用户极不愿意为小工具下载安装软件。做法：

1. 预先收集一批**软件下载站域名**（如各类下载站/大站域名）。
2. 对每个幸存词检查 SERP：若结果几乎全是下载站或大站域名 → 该需求很可能还没有 Web 版供给（技术门槛/场景门槛造成的错位）→ **机会词**。
3. 词里明确带「在线」词缀的，用户对 Web 版期待最强，优先级更高。

## 3.5 产出

`03_filtered/survivors.csv`：幸存词 + 各项竞争指标 + 是否「下载站错位」标记。交给阶段 4 人工验证。

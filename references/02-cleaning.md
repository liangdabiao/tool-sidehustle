# 阶段 2：清洗策略

目标：阶段 1 追求「多」，会带来海量冗余；清洗是为了**减少阶段 3 的查询量**（SERP/权重/搜索量查询都有成本）。产出：按「核心词类别」分组后的代表词清单。

常规的违规词、无效词、无意义词、无规则词清洗不赘述，重点两步：

## 2.1 去除延伸词

「图片压缩工具哪个好」「哪个软件可以压缩图片」「图片压缩工具怎么用」本质是同一个需求：「图片压缩工具」。只保留需求的基本描述，去掉延伸出来的疑问/问题词。

**判断规则：长尾词包含以下疑问词表中的词 → 直接去除。**

疑问词表（原文验证有效，可按数据补充）：

| | | | | |
|---|---|---|---|---|
| 哪里 | 多少 | 有没有 | 不够 | 好用 |
| 哪有 | 几个 | 能不能 | 不行 | 最好 |
| 哪个 | 几种 | 是不是 | 不好 | 不用 |
| 哪能 | 有啥 | 要不要 | 不会 | 没有 |
| 哪几 | 什么 | 好不好 | 不能 | 可以 |
| 哪样 | 怎么 | 行不行 | 无法 | 还是 |
| 哪种 | 怎样 | 够不够 | 无需 | 需要 |
| 哪些 | | 可不可以 | 不了 | 好吗 |
| 那个 | | 能不能够 | 不可以 | 好么 |
| 那些 | | | 没办法 | 可能 / 大概 / 大约 / 应该 |

不必担心误杀：能搜到「图片压缩工具哪个好」，就一定有人搜过「图片压缩工具」——数据量足够大时的固定规律。如果某需求只剩疑问词形态的词，说明需求量不值得做。

## 2.2 去除「重复」词（核心词提取）

「图片压缩软件」「图片压缩工具」「图片压缩助手」「一键压缩图片」「自动压缩图片」「在线图片压缩」全是同一个需求，核心是「图片+压缩」。「软件/在线/工具/助手/一键/自动」这类词不体现需求核心，连同停用词一并去掉。

**判断标准：越普遍的词越没有代表性。**

流程：
```
图片压缩工具 → 分词 → 图片|压缩|工具 → 去无效词 → 图片|压缩
图片压缩软件 → 分词 → 图片|压缩|软件 → 去无效词 → 图片|压缩   ← 同类
```

1. 剩余核心词（排序后）作为类别键，相同键 = 同一类别。
2. 批量查询时每类抽 1 个代表词即可；**代表词选最短的**——最短词最能反映真实竞争情况（5118 实证：查「markdown转word在线编辑器」得 0 条，查「markdown转word」得 100 条）。
3. 对剩余词按全局词频升序排序：词频越低越有代表性。

**无效词表的构成规则**：无效词表 = 通用词 ∪ 全局词频 top 词，**并强制剔除「主词根与对象词白名单」**（图片/视频/音频/文本/文档/pdf/水印/语音…，挖掘时维护此白名单，脚本已内置 `--extra-objects`）——对象词承载需求核心，即使在本语料中词频最高也保留，否则聚类键会退化（如「在线压缩图片」只剩键「压缩」，会与「在线压缩视频」误合并）。

## 2.3 残余处理

清洗后仍会剩一些「零散」词：根据具体数据人工看一批，提取普遍特征词再做批量清洗。

核心词提取效果示例（原文）：「在线视频翻译软件」→ 类别键「视频,翻译,图片」；同批「在线视频翻译下载」→「视频,翻译,下载」——分词+去无效词后自然聚类。

产出格式建议（`02_cleaned/representatives.csv`）：`cluster_key,representative,all_words_json`
